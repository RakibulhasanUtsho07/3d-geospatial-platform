# P2.6 — Dynamic map multi-viewport workload

## Objective

Exercise the actual Cesium map lifecycle through repeated pan/zoom movements, overlapping viewport fetches, request cancellation, and Cesium geometry staging. This complements the P2.4 cold/warm single-fixture load and the P2.5 repeatability report.

## Run

The benchmark has an isolated Playwright configuration so it does not change or duplicate the general map-browser suite:

```bash
npm run test:map-dynamic-viewport-workload
```

The app should be served at `http://127.0.0.1:3000` (override with `MAP_E2E_BASE_URL`). The command saves `artifacts/p2.6-dynamic-map-workload/dynamic-viewport-workload.json` and `SHA256SUMS.txt`. Override the output directory with `P2_6_EVIDENCE_DIR`.

## Workload and assertions

- Uses a deterministic 36-building Polygon fixture plus 24 road features.
- Delays the first building and road fixture responses to provoke overlapping camera intent and stale-request cancellation.
- Performs four zoom-outs, two zoom-ins, and a canvas drag-pan.
- Measures building/road request start/end durations, cancellation and error outcomes, number of unique viewport bounds, final staged feature/road counts, time from movement start to the matching latest building stage, JavaScript heap snapshots where available, canvas dimensions, and a 1.2-second animation-frame interval sample.
- Checks that the latest building viewport request is the viewport ultimately staged, at least two unique viewport bounds were requested for both layers, expected features/roads were staged, cancellation was observed, and no non-cancellation API fetch errors remained.
- Binds the report to the synthetic input fixture with SHA-256 and writes a checksum for the JSON report.

## Interpretation / limitations

This test stresses the production map component, viewport request manager, road-layer manager and Cesium staging with a multi-feature synthetic API response. It does **not** claim to benchmark a real OGC 3D Tiles multi-GLB hierarchy or the complete Dhaka dataset. P2.4/P2.5 still use the separate one-content synthetic 3D Tiles fixture. This distinction is deliberate so viewport request/cancellation behavior is measurable without confusing it with GLB tile traversal.

JavaScript heap measurements are coarse and browser-dependent; GPU/driver memory is not measured. Request timings and animation-frame intervals run under headless Chromium/SwiftShader and must not be interpreted as physical-GPU performance. The report records results rather than imposing an uncalibrated latency threshold.

CI stores `p2-6-dynamic-map-workload` for 14 days. The generated report should be reviewed for latest-viewport parity, cancellation count, non-cancellation failures, stage counts, input hash, and checksum before using its timings as a baseline.
