# P2.3 — Fixed-camera GeoJSON / 3D Tiles alignment capture

## Goal

Capture repeatable browser evidence for the Dhaka placement fixture, using the same camera preset to compare the selected source GeoJSON footprint with the OGC 3D Tiles GLB fixture.

The existing metadata review remains a separate check. It validates the WGS84 transform, bounding-volume region and a rectangular footprint envelope; it does not create a rendered image. This browser capture adds runtime loading, screen-projected corner checks and PNG evidence.

## Local run

Run from the repository root:

```bash
npm install
npm run copy:cesium
npm run build:dhaka-3d-tiles-fixture
npm run review:dhaka-3d-tiles-alignment
```

Start the app in another terminal so the generated fixture is publicly served. The normal `predev` hook performs the asset/fixture generation steps:

```bash
npm run dev
```

In a third terminal:

```bash
npm run test:dhaka-3d-tiles-camera-alignment
```

The Playwright configuration uses headless Chromium with SwiftShader. The test visits the standalone page once for each camera preset: `north`, `east`, `south`, `west` and `oblique`.

## Evidence output

The test writes to `artifacts/p2.3-camera-alignment/` by default:

- `view-<preset>.png`: fixed-viewport (1600×950) side-by-side screenshot, one per camera; the capture keeps the same viewport used for pixel-residual checks.
- `camera-alignment-review.json`: source, selected-feature, GeoJSON preview, tileset and GLB SHA-256 hashes; browser/Cesium versions; camera values; per-corner pixel residuals; and each screenshot SHA-256.

Override the directory with `P2_3_EVIDENCE_DIR`. CI uploads the directory as the `p2-3-dhaka-camera-alignment-evidence` artifact (14-day retention).

## Pass conditions

- Both Cesium viewers load the baseline/fixture successfully.
- Both viewers report the same fixed camera pose (maximum absolute field delta ≤ `1e-8`).
- The loaded Cesium tileset's runtime world-space bounding-sphere centre is within `1` metre of the fixed review target.
- Four expected/actual footprint corners project into both viewports.
- Each projected footprint-envelope corner residual is ≤ `8` pixels.
- All five views use identical input hashes for the source dataset, selected feature, tileset and GLB.
- Every captured PNG has a SHA-256 recorded in the manifest.

## Interpretation and limitations

The 3D Tiles content is a deterministic synthetic rectangular prism matched to the source feature's bounding envelope. This is a placement/camera reproducibility gate—not proof of the exact source Polygon/MultiPolygon outline, true building height, facade resemblance, or photogrammetric accuracy. The GeoJSON panel shows the same source feature extruded to the fixture's nominal 8 m height for visual context.

PNG hashes are immutable evidence for an exact run. Pixel hashes may differ across operating systems or renderer versions, so semantic tolerance checks—not cross-platform equality of whole-image hashes—are the gate.

Cold/warm render time and memory comparison are intentionally a later stage. Do not infer those metrics from this capture test: run them only after the same-view alignment gate is passing.
